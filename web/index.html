01 · Учебный портал

Это интерфейс Academy. Для него не нужно разворачивать Kafka, Kubernetes или Docker. Старый портал останови через Ctrl+C. Для тестов используй отдельный checkout и приватный каталог данных.

Подготовить и запустить

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v11-dev.txt
python portal.py

Проверить из второго терминала

curl -fsS http://127.0.0.1:8080/api/version
Критерий результата

Открывается http://127.0.0.1:8080/; API версии отвечает. Для сохранения старых черновиков не меняй origin браузера (localhost и 127.0.0.1 различаются).

Открыть портал · остановка: Ctrl+C в терминале портала.

02 · Основная лаборатория LAB-001

Работай в отдельной чистой копии stable, не в запущенном портале. CLI start может переключить или создать ветку student/lab-001. Если ветка уже есть на origin, сначала явно извлеки её и проверь совместимость; не сбрасывай изменения.

Создать новую копию, если её ещё нет

cd ~
git clone -b academy/stable git@github.com:dneprov808-sudo/devops-lead-lab.git academy-student
cd academy-student
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v11.txt
python academy.py doctor
python academy.py start --minutes 60

После самостоятельной реализации

python academy.py test
python academy.py report
Критерий результата

Оригинальные тесты проходят на своём решении; REPORT.md заполнен. Коммит и push только после ручного review diff. Тест-кнопка портала проверяет именно checkout портала, а не другой каталог.

Docker ComposeКорень stable · 18111

03 · Production Simulator · Light

Один PostgreSQL, один Kafka, Redis, API и worker. Начинай с этого варианта перед HA. Проверяй локальный Docker context; не запускай одновременно с HA или legacy v8.

Проверить и поднять

docker context show
docker context inspect --format '{{.Endpoints.docker.Host}}'
docker compose -f production_v11/compose.yaml --profile light config --quiet
docker compose -f production_v11/compose.yaml --profile light up -d --build

После готовности

curl -fsS http://127.0.0.1:18111/stats
python3 production_v11/smoke.py
Критерий результата

API отвечает, bounded smoke проверяет обработку и восстановление worker. Это не HA.

Остановить / очистить

docker compose -f production_v11/compose.yaml --profile light down

Docker Compose / AdvancedКорень stable · 18112

04 · Production Simulator · HA

Три Kafka, Patroni/etcd, Redis Sentinel и балансировщик. Сначала останови Light и старые стенды; требуются свободная память, диск и локальный /var/run/docker.sock. Не используй remote Docker.

В одном терминале: определить команду

unset DOCKER_HOST DOCKER_CONTEXT
ha() {
  docker --host unix:///var/run/docker.sock compose \
    -p academy-v12-ha \
    -f production_v11/compose.yaml \
    -f production_v11/compose.ha.yaml \
    -f production_v11/compose.v12.yaml --profile ha "$@"
}

Развернуть

ha config --quiet
ha up -d --build
ha ps -a

После готовности и проверки context того же сокета

curl -fsS http://127.0.0.1:18112/health
python3 production_v11/ha_drill_v12.py --confirm-local-lab
python3 production_v11/topology_v12.py --confirm-local-lab
python3 production_v11/quorum_v12.py --confirm-local-lab
Критерий результата

Все три проверки PASS; это ограниченная проверка стенда, не гарантия SLA. При BLOCKED остановись и разберись с зависимостями. Аварии только после baseline.

Остановить / очистить

ha down

Тома сохраняются. Не добавляй -v. Сценарии отказа описаны в инструкции.

kind / DockerКорень stable · отдельный kubeconfig

05 · Kubernetes / Helm

Требуются локальные Docker, kind, kubectl, Helm 3 и Python. Создай кластер academy-v11 только если его ещё нет. Не используй default kubeconfig для упражнений.

Базовый кластер

bash v11-labs/k8s/lab.sh create
bash v11-labs/k8s/lab.sh install
bash v11-labs/k8s/lab.sh verify

Выбрать дополнительную задачу

python3 v12-labs/k8s/lab.py list

Пример KADV-01: только свой namespace

python3 v12-labs/k8s/lab.py setup KADV-01 --confirm-local-lab

После самостоятельной диагностики

python3 v12-labs/k8s/lab.py verify KADV-01 --confirm-local-lab
Критерий результата

Verifier проходит после исправления; CNI, CSI, HPA и Argo требуют отдельных prerequisites. Сохрани evidence до удаления namespace.

Подготовка kind и Helm ↗. Удаление кластера уничтожает учебное состояние; делай только по инструкции после сохранения доказательств.

WSL / disposable VMКорень stable → isolated namespace

06 · Linux и сети

Нужны iproute2, util-linux, nftables, tcpdump, dnsutils, dnsmasq, openssl и Python. Запускай только в расходуемой среде; не обходи запреты user namespaces.

Войти в sandbox

bash v12-labs/linux/sandbox.sh --confirm-local-lab

Внутри sandbox после исправления route

python "$ACADEMY_LINUX_ROOT/verify.py" route
Критерий результата

Проверка фактической маршрутизации проходит. DNS, firewall, TLS и packet capture выполняются по README; systemd и cgroups — в отдельной VM.

Disposable VM / local providerОтдельная рабочая копия

07 · Ansible / Terraform

Ansible — локальная роль и идемпотентность; Terraform — только local provider, без облака. Скопируй Terraform-папку в новый каталог, изучи plan до apply.

Ansible: проверка после решения

python3 v12-labs/iac/ansible/verify.py

Terraform: подготовка новой копии

WORK=$(mktemp -d "$HOME/academy-terraform.XXXXXX")
cp -r v12-labs/iac/terraform/. "$WORK/"
cd "$WORK"
terraform init
terraform test
Критерий результата

Ansible: повторный запуск changed=0; Terraform: reviewed plan, drift и повторная проверка. Не запускай apply до анализа плана.

08 · CI/CD

Сначала локальная сборка артефакта. Jenkins и GitLab CI — отдельные необязательные локальные установки; не подключай production runner.

Build + verify

python3 -m unittest test_pipeline_v12 -v
python3 v12-labs/cicd/pipeline.py build v12-labs/cicd/source.json bundle
python3 v12-labs/cicd/pipeline.py verify bundle
Критерий результата

Артефакт проверяется; promotion только по вручную проверенному SHA256. Сравни tampered copy по инструкции.

09 · Приёмка самой Academy

Это тесты платформы, а не твоих компетенций. Python 3.12–3.14, Node 22, зависимости dev. E2E требует Chromium; Compose требует Docker.

Регрессия

python release/compatibility.py
python release/gate.py

Браузер + Compose

python -m playwright install --with-deps chromium
python release/gate.py --full
Критерий результата

PASS / FAIL / BLOCKED. Отсутствие Docker, браузера или сканеров не считается PASS. Security и живые HA/K8s проверяются отдельно.
