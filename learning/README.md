# Academy Engineering Pro v3 — ACADEMY-010

## Быстрый старт (WSL Ubuntu)

Новый checkout, без перезаписи существующего решения:
    git clone -b academy/engineering-pro-v3 https://github.com/dneprov808-sudo/devops-lead-lab.git devops-lead-lab-v3
    cd devops-lead-lab-v3
    python3 portal.py

Открой http://127.0.0.1:8080. Останови предыдущий портал Ctrl-C, если порт занят. При отсутствии зависимостей: sudo apt install git python3 python3-yaml curl bash. Для приватного репозитория нужен настроенный Git-доступ; для Handoff Monitor отдельно gh. Docker нужен только для реальных стендов. Не запускай Docker или kubectl против production-контекста. Не включай платный CI. Не размещай портал в интернете.

## Что изменилось

- 20 инженерных справочников в learning/knowledge.json: принципы, диагностические команды, порядок расследования, типовые ошибки, Lead-вопрос и документация. Поиск по содержанию, раскрывающиеся карточки, копирование команд. Команды с placeholder требуют подстановки своего учебного имени; примеры PromQL/SQL выполняются в соответствующей консоли. Отдельные локальные стенды RabbitMQ, Kubernetes, Terraform, Vault, HAProxy и OpenTelemetry в этой версии не включены.
- 16 дополнительных практических заданий (7 новых) в practice/catalog.json, на существующих 6 профилях Compose. Новые темы: Kafka replay, MVCC/VACUUM, restore drill, Patroni switchover, Redis stampede, Nginx timeout budget, Prometheus SLO. Не дублируют основной LAB-001. Сначала проверь docker compose config в локальном контексте. Реальные контейнерные проверки всё ещё не выполнены в среде разработки.
- 80 вопросов по 20 темам в web/app.js; по четыре на тему, два уровня; при score>=3 выбираются продвинутые, вопросы чередуются в пределах уровня. Это локальная самооценка, не оценка ChatGPT. Интервальные повторения сохраняются в браузере по существующим правилам.
- 17 синтетических инцидентов в learning/incidents.json: симптомы, отдельно раскрываемая диагностика, подсказка, собственная гипотеза, разбор. Разбор открывается после непустого ответа; это учебное UX-ограничение, не секрет/экзаменационная защита (JSON доступен локально). Решений LAB-001 или практических заданий не добавлено.
- 5 архитектурных упражнений в learning/design.json: событийнная обработка заявок, HA PostgreSQL, безопасная доставка Kubernetes, observability, внутренняя платформа. Требования и цифры синтетические, не данные MOEX. Готовых решений нет. Есть критерии защиты, шаблон ADR/Runbook, копирование запроса для наставника в проект «Учеба».
- 4 калькулятора: SLO/time error budget и burn rate, Kafka drain time, время заполнения диска, кворум. Это модели с допущениями, не гарантия SLA. Для request-based SLO нужен расчёт по числу запросов.
- История сохранённых результатов в GitHub: отдельная вкладка. Чтение одного SHA ветки student/practice-results, валидация пути, размера, режима файла и схемы результата; не более 300 файлов в лексикографическом порядке путей, не сортировка по дате. Повреждённые записи не раскрываются. Если ветки нет, показывается пустая история; ошибки доступа — BLOCKED. Сохранение по прежней кнопке осталось прежним: явное подтверждение → отдельный Git index → non-force push → read-back. Сырые ответы/логи не сохраняются. Никаких автоматических записей из вкладок справочника, инцидентов или архитектуры. История отражает самоотчёты и метаданные тестов, не подтверждённые компетенции.

## Как заниматься

20 минут: 1 справочник → вопрос → повторение.
60 минут: 1 тема → одно практическое задание или часть задания → тест/самопроверка → сохранение результата.
120 минут: стенд, отказ/восстановление, измерения, ADR или защита с наставником.
Основная программа управляется STATE; дополнительные задания не заменяют LAB-001. Code Review и независимый экзамен выполняются в ChatGPT, без API. Официальные результаты утверждает только Orchestrator по существующему протоколу. Плановый агент остаётся dry-run. Сохранение результатов не является Handoff и не меняет STATE.
